# Task Tracker

Full-stack task management application: create, edit and track tasks with statuses,
tags, search, filtering, sorting and pagination.

Angular single-page frontend, Spring Boot REST API, PostgreSQL storage.

## Features

- Create, edit and delete tasks (deletion requires confirmation)
- Quick status change directly from a task card
- Task statuses: `TODO`, `IN_PROGRESS`, `DONE`
- Many-to-many tags; unknown tag names are created automatically
- Case-insensitive search by title
- Filtering by status and by tag, combinable with search
- Pagination and sorting by creation date
- Server-side validation with field-level error messages
- Unified error format for the whole API
- Loading, error and empty states on the frontend; background refresh keeps the
  current list visible instead of blanking the screen
- Responsive dark UI
- Interactive API documentation via Swagger UI

## Architecture

```
Angular frontend  (http://localhost:4200)
        |
        |  REST / JSON
        v
Spring Boot API   (http://localhost:8080)
        |
        |  JPA / Hibernate
        v
PostgreSQL        (localhost:5432)
```

Backend layers:

```
Controller  ->  Service  ->  Repository  ->  Entity
```

- **Controller** handles HTTP only: request mapping, validation trigger, status codes.
- **Service** owns business logic and transactions.
- **Repository** is Spring Data JPA; dynamic filtering is built with JPA Specifications.
- **Entity** maps to database tables. Schema is owned by Flyway, Hibernate runs with
  `ddl-auto: validate` and only verifies the mapping against the real schema.

Entities are never exposed over HTTP. Separate DTOs are used for requests
(`TaskCreateRequest`, `TaskUpdateRequest`, `TaskStatusUpdateRequest`) and for
responses (`TaskResponse`, `PageResponse<T>`, `ApiError`).

CORS is configured centrally for `http://localhost:4200`.

## Task model

| Field | Type | Notes |
| :--- | :--- | :--- |
| `id` | Long | generated by the database |
| `title` | String | required, max 120 characters |
| `description` | String | optional |
| `status` | Enum | `TODO`, `IN_PROGRESS`, `DONE` |
| `tags` | String[] | many-to-many, exposed as a list of names |
| `createdAt` | LocalDateTime | set automatically on creation |
| `updatedAt` | LocalDateTime | updated automatically on every change |

## API

| Method | Endpoint | Description |
| :--- | :--- | :--- |
| `GET` | `/api/tasks` | Paginated task list with filtering, search and sorting |
| `GET` | `/api/tasks/{id}` | Single task by id |
| `POST` | `/api/tasks` | Create a task |
| `PUT` | `/api/tasks/{id}` | Full update of a task |
| `PATCH` | `/api/tasks/{id}/status` | Change only the status |
| `DELETE` | `/api/tasks/{id}` | Delete a task |

Query parameters of `GET /api/tasks` (all optional, combined with AND):

| Parameter | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `status` | `TODO` \| `IN_PROGRESS` \| `DONE` | — | filter by status |
| `tag` | String | — | filter by tag name, case-insensitive |
| `search` | String | — | substring search in title, case-insensitive |
| `page` | int | `0` | page number, zero-based |
| `size` | int | `20` | page size, capped at 100 |
| `direction` | `asc` \| `desc` | `desc` | sort order by `createdAt` |

Example:

```
GET /api/tasks?status=TODO&tag=backend&search=filter&page=0&size=10&direction=desc
```

The response is a page object; tasks are in the `content` field:

```json
{
  "content": [
    {
      "id": 3,
      "title": "Add filtering and pagination",
      "description": "Filters by status and tag, search by title",
      "status": "TODO",
      "tags": ["backend", "urgent"],
      "createdAt": "2026-08-06T12:30:00",
      "updatedAt": "2026-08-06T12:30:00"
    }
  ],
  "page": 0,
  "size": 10,
  "totalElements": 6,
  "totalPages": 1,
  "first": true,
  "last": true
}
```

Interactive documentation:

- Swagger UI: `http://localhost:8080/swagger-ui.html`
- OpenAPI JSON: `http://localhost:8080/v3/api-docs`

## Running locally

### Prerequisites

| Tool | Version |
| :--- | :--- |
| JDK | 21 |
| Maven | 3.9+ |
| Node.js | 20.19+ or 22.12+ |
| Docker Desktop | required for the PostgreSQL container |

### 1. Clone the repository

```bash
git clone https://github.com/dimash-dev/task-tracker.git
cd task-tracker
```

### 2. Start PostgreSQL

From the repository root:

```bash
docker compose up -d db
```

Check that the container is healthy:

```bash
docker compose ps
```

### 3. Start the backend

```bash
cd backend
mvn spring-boot:run
```

Flyway applies the migrations on startup. The API is available at
`http://localhost:8080`.

### 4. Start the frontend

In a second terminal:

```bash
cd frontend
npm install
npm start
```

### 5. Open the application

`http://localhost:4200`

## Database

PostgreSQL 16 runs in a Docker container defined in `docker-compose.yml`.
The schema is managed by Flyway; migrations live in
`backend/src/main/resources/db/migration`:

| Migration | Contents |
| :--- | :--- |
| `V1__init.sql` | tables `tasks`, `tags`, `task_tags`; constraints and indexes |
| `V2__seed.sql` | small demo dataset: 6 tasks, 5 tags |

Connection settings:

| Setting | Value |
| :--- | :--- |
| Host / port | `localhost:5432` |
| Database | `task_tracker` |
| User | `task_tracker` |
| Password | `task_tracker` |

These are local development credentials defined in `docker-compose.yml`
and used as defaults in `application.yml`. They can be overridden with
environment variables:

| Variable | Default |
| :--- | :--- |
| `DB_URL` | `jdbc:postgresql://localhost:5432/task_tracker` |
| `DB_USERNAME` | `task_tracker` |
| `DB_PASSWORD` | `task_tracker` |
| `SERVER_PORT` | `8080` |

To stop the database while keeping its data:

```bash
docker compose down
```

Data is stored in the named volume `postgres-data` and survives restarts.

## Validation and error handling

Validation rules are enforced on the server:

- `title` is required and limited to 120 characters
- tag names are non-empty, up to 50 characters
- `status` accepts only `TODO`, `IN_PROGRESS`, `DONE`

The database enforces the same rules independently: a `CHECK` constraint on
`status`, a length limit on `title` and a uniqueness constraint on tag names.

All errors are returned in a single format produced by a
`@RestControllerAdvice` handler:

```json
{
  "status": 400,
  "error": "Bad Request",
  "message": "Проверьте правильность заполнения полей",
  "path": "/api/tasks",
  "timestamp": "2026-08-27T15:43:02.551",
  "fields": { "title": "Заголовок обязателен" }
}
```

`fields` carries per-field messages for validation errors and is empty otherwise.

| Status | When |
| :--- | :--- |
| `400` | validation failure, malformed JSON, invalid enum or parameter value |
| `404` | task not found, unknown endpoint |
| `405` | HTTP method not supported by the endpoint |
| `500` | unexpected server error; details are logged, not returned to the client |
